# Database

blueprint1 stores user-owned ERD blueprints and immutable saved versions in
Postgres. The schema is intentionally small: Supabase Auth owns user identity,
while this app stores blueprint data keyed by the Supabase user id.

## Connection Model

The app has two database connection purposes:

- **Runtime app connection**: `DATABASE_URL`
- **Migration connection**: `DIRECT_URL`, falling back to `DATABASE_URL`

For serverless production deploys, `DATABASE_URL` should use the Supabase
transaction pooler, usually port `6543`. The `postgres-js` client is configured
with `{ prepare: false }`, which is compatible with transaction pooling.

Drizzle generation and migrations should use a direct or session-pooler
connection, usually port `5432`.

## Schema Source

The Drizzle schema lives in:

```text
src/db/schema.ts
```

Generated SQL migrations live in:

```text

```

Current migrations:

## Tables

### `blueprints`

Stores the owner-visible blueprint record and the current uncommitted draft.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid` | Primary key, generated by the database. |
| `owner_id` | `uuid` | Supabase `auth.users.id`; no local profile table. |
| `title` | `text` | User-visible blueprint title. |
| `is_public` | `boolean` | Whether the latest saved version is visible by share link. Defaults to `false`. |
| `public_slug` | `text` | Unique opaque share slug; null when private or unpublished. |
| `draft_sql` | `text` | Uncommitted SQL draft; owner-only. |
| `draft_positions` | `jsonb` | Uncommitted node positions; owner-only. |
| `draft_updated_at` | `timestamptz` | Present when a draft exists. |
| `created_at` | `timestamptz` | Creation timestamp. |
| `updated_at` | `timestamptz` | Updated by app writes and Drizzle `$onUpdate`. |

Indexes:

- `blueprints_owner_id_idx` on `owner_id`
- `blueprints_owner_updated_idx` on `owner_id, updated_at`
- unique index/constraint on `public_slug`

### `blueprint_versions`

Stores saved version history for each blueprint.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid` | Primary key, generated by the database. |
| `blueprint_id` | `uuid` | Foreign key to `blueprints.id`; cascades on delete. |
| `sql` | `text` | Saved SQL text for this version. |
| `graph` | `jsonb` | Server-computed parsed ERD model. |
| `positions` | `jsonb` | Saved node positions. Defaults to `{}`. |
| `note` | `text` | Optional version note. |
| `created_at` | `timestamptz` | Version creation timestamp. |

Indexes:

- `blueprint_versions_blueprint_idx` on `blueprint_id`
- `blueprint_versions_blueprint_created_idx` on `blueprint_id, created_at`

## JSON Shapes

`positions` and `draft_positions` are stored as:

```ts
type NodePositions = Record<string, { x: number; y: number }>;
```

`graph` stores the parsed ERD model:

```ts
{
  tables: ErdTable[];
  relations: ErdRelation[];
}
```

The graph is committed only after the server parses and validates SQL. The
client preview graph is not trusted as the persisted source of truth.

## Ownership And Authorization

`owner_id` stores the Supabase authenticated user id directly.

Private reads and writes must include the authenticated user id, for example:

```text
where blueprints.id = blueprintId
  and blueprints.owner_id = userId
```

The app uses Drizzle with a direct Postgres connection, so Supabase Row Level
Security is not the runtime authorization boundary. RLS may be added later as
defense-in-depth, but application-level owner checks remain required.

## Drafts And Versions

The product uses a draft-to-version model:

- Draft data lives on `blueprints`.
- Saved history lives in `blueprint_versions`.
- Saving as a new version inserts a version row and clears the draft.
- Restoring an old version copies that version into the draft fields.
- Deleting a blueprint cascades to its versions.

This keeps saved history immutable while still allowing autosaved editing state.

## Public Sharing

Public share pages read by `public_slug` only when `is_public = true`.

Public responses expose the latest saved version:

- title
- latest saved SQL
- latest parsed graph
- latest node positions
- updated timestamp

Public responses do not expose owner id, draft fields, or private version
history.

When a blueprint is unpublished, `public_slug` is set to null. This invalidates
the previous share URL.

## Validation Limits

Server-side validation currently enforces:

- title length: 1 to 120 characters
- SQL input: up to 100,000 characters
- version note: up to 280 characters
- graph size: up to 50 tables
- graph size: up to 100 columns per table
- graph size: up to 1,000 columns total

These limits protect server parsing, ELK layout, and browser canvas rendering.

## Migration Workflow

After changing `src/db/schema.ts`, generate and review a migration:

```bash
pnpm drizzle-kit generate --name=your_change_name
```

Then apply it:

```bash
pnpm drizzle-kit migrate
```

Use `DIRECT_URL` for generation and migration whenever possible. Do not run
migrations through the transaction pooler.
